# 功能需求基线

## 学生端

1. 手机扫描二维码直接进入网页，无需安装应用。
2. 使用学号、姓名和一次性激活码进行身份核验。
3. 仅显示当前学生所属专业在各教学组的配额、余量和状态。
4. 一次提交后锁定，重复提交不能覆盖既有结果。
5. 满额或抢选未开放时给出明确提示。

## 管理端

1. 自定义抢选活动标题和页脚制作人名称。
2. 专业可新增、重命名、排序、启停及安全删除。
3. 教学组可新增、重命名、排序、启停及安全删除。
4. 专业或教学组数量变化后，配额矩阵自动扩展；每格配额可独立修改。
5. 导入学生名单并生成激活码；导出选择结果和未选名单。
6. 开放或关闭抢选，手动补位、撤销，并记录审计日志。
7. 二维码可进入浏览器全屏展示。
8. 二维码两侧同时展示已选/未选统计及未选学生名单。

## 关键约束

- 选择写入使用数据库事务，任何专业 × 教学组配额均不得超额。
- 已被学生或配额引用的专业、教学组不能直接删除；应先停用或迁移数据。
- 结构和配额只允许在抢选关闭状态修改。
- 正式数据库、备份、密钥和学生隐私不得进入公开仓库。
